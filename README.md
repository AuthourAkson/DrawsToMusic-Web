# DrawMusic —— 画出声音

一个「把线条变成音乐」的网页乐器。**零依赖、零构建**，双击 `index.html` 就能用。

最初是为了救回一幅在 play_music_theory 上被「64 条笔迹上限」吃掉的画而写的，
所以它在几件事上刻意做得比原站更硬。

---

## 快速开始

1. 双击 **`index.html`**（Chrome / Edge / Firefox 都行，不需要装任何东西、不需要联网）
2. 在纸上按住鼠标（或手指）拖动 —— **横轴是时间，纵轴是音高**
3. 按 **空格** 播放

第一次点击页面才会启动音频（浏览器的自动播放限制）。

---

## 导入你原来的画

点右上角 **「⬇ 导入作品」**，然后：

- 粘贴 play_music_theory 的**分享链接**（`https://playmusictheory.net/play#p=...`）
- 或直接粘贴那一长串 `j…` / `d…` 代码
- 或把本程序导出的 **`.json`** 拖进去 / 选文件
- 也可以用浏览器控制台里的 `localStorage.getItem('pmt.draft')` 内容

解析后会显示 **条数 / 采样点 / 页数**，右边有实时预览。

### 关于「画布比例」那一步

play_music_theory 存在数据里的 `a`（高/宽）是**保存那一刻的浏览器窗口比例**，不是你画的时候的比例 ——
开着 DevTools 或缩过窗口，这个值就是错的。

所以导入面板里可以像挑照片一样点选比例，预览会立刻跟着变，选到形状对为止。

> 判断技巧：线条应该看起来自然、不被压扁或拉长。电脑宽屏一般在 **0.45 ~ 0.65** 之间。

导入之后，这个比例会被**永久记住**（存进 `piece.ar`），以后无论怎么缩放窗口，画都不会变形。

## 和 play_music_theory 的区别

| | play_music_theory | DrawMusic |
|---|---|---|
| 打开作品时的笔迹上限 | **硬编码 64 条**，多出来的永久丢失 | **无上限** |
| 同时发声的音 | 固定 118 个槽位，画多了就不出声 | 事件驱动 + 192 声部动态池，密度自适应 |
| 画布比例 | 跟随当前窗口，换个屏幕就拉伸 | 作品自带比例，任何窗口都不变形 |
| 音高映射 | 每列最多取 3 个音簇 | 一样（保留原配方） |
| 导出 | PNG/JSON 需要手写脚本；WAV/MIDI 在付费面板里 | 工具栏一键 PNG / JSON / WAV |
| 导出画质 | 受画布尺寸限制 | PNG 可输出 2400px 宽 |
| 开源 | 否（© 保留所有权利） | 代码全在这儿，随便改 |

**保留的原站配方**：五声音阶默认（乱画也好听）、每列取音簇中点、最多 3 个音、
墨迹的「实心芯 + 两层随机虚线」笔刷、软削波 + 延迟总线、播放头按音频延迟对齐。

## 这些参数是什么意思

- **细分（格/拍）**：4 格/拍 = 16 分音符。原站是 3 格/拍。
- **长度**：一小节 = 4 拍。8 拍 = 两小节循环。
- **音阶 / 主音**：只有五声音阶以外的音阶才会出现半音，画起来更容易「跑调」但也更像旋律。
- **画布比例**：就是作品的高/宽。改它会立刻重排画布，**不会**改变你已画的相对位置。

## 数据格式

```jsonc
{
  "v": 1,
  "bpm": 120,
  "scale": "pentatonic",   // 11 种
  "key": 0,                // 0=C … 11=B
  "stepsPerBeat": 4,
  "beats": 8,
  "rows": 32,              // 纵轴 32 行音高
  "ar": 0.62,              // 画布 高/宽 —— 关键字段
  "pages": [               // 至少一页
    [ { "color": 3, "pts": [[0.12, 0.34], [0.13, 0.36]] } ]
  ]
}
```

坐标是 **0~1 的浮点**，与画布像素完全无关，所以无损、可任意缩放。

## 已知限制

- 音频线程用 `AudioWorklet`；老浏览器会**自动回退**到主线程合成（会稍微吃 CPU，可能偶有爆音）。
- 同时发声的音超过约 60 个时，会开始「抢占」最旧的声部 —— 这是防止爆音的保护，不是 bug。
- 没有做 MIDI 导出（原站有，但那是付费功能；需要的话 `audio.js` 里的音符事件已经可以直接转成 MIDI）。

## 常见问题

**Q：导入后图被裁掉一半 / 只看到左上角？**
v1.1 已修。原因是 canvas 只设了 `width/height` 属性、没设 CSS 尺寸 ——
在 Windows 125%/150% 显示缩放下（`devicePixelRatio` 不是 1），
canvas 元素会按 `W×1.5` 的物理尺寸撑开，被纸张的 `overflow:hidden` 裁掉右下角。
现在 `resize()` 里显式设了 `cv.style.width/height`。**如果你的版本还是旧的，重新打开一次页面即可。**

**Q：导入 `.json` 后一片空白？**
v1.1 已修。之前只认本程序的格式（`{pages:[[…]]}`），
而早期脚本导出的是 play_music_theory 格式（`{v,a,m,b,t,g,s}`），会被吞成空画布。
现在两种都认。另外解析后如果一条笔迹都没有，会**明确报错**而不是静默变空。

**Q：导入后形状是歪的 / 被拉长？**
导入面板左侧点选「画布比例」，预览会实时更新，挑到线条自然为止。

**Q：没有声音？**
- 先点一下页面里的「播放」（浏览器要求一次用户手势才允许出声）
- 检查右下角音量 / 系统静音
- iOS 的侧边静音开关会掐掉 Web Audio，拨到静音状态试试
- 极老浏览器会回退到主线程合成，可以用 `F12 → Console` 看有没有「AudioWorklet 不可用」的提示

**Q：画得太多会不会卡？**
300~500 条笔迹没问题。静态图层缓存在离屏 canvas 上，只有内容变化才重画，
播放头每帧单独合成。

## 为什么拖笔是 0 延迟

v1.2 之前其实很卡（画到几百条就明显跟手不上）。三处热点：

| 问题 | 代价 |
|---|---|
| 每帧重设 `inkCv.width` —— 设 `canvas.width` 会**重新分配整块位图** | 每帧 ~4.5MB 重分配 + 清空 |
| `updateStats()` 写在每次 `pointermove` 里，遍历全部采样点 | 每次移动 O(全部点) |
| `buildNoteData()` 用 `BigInt`，每次移动重建 | **5.5 ms / 次** |

现在的做法：

1. **静态层缓存**：网格 + 已完成的笔迹画在离屏 canvas 上，只有内容变化才重画。
   尺寸没变就**绝不重设 `width`**。
2. **实时笔触走单独通道**：正在画的那条每帧直接叠在合成结果上，
   用的还是同一套三层笔刷（同样的随机种子），所以**松手前后长得一模一样，不会"跳"一下**。
3. **松手时直接烤进静态层**（`bakeStroke`），不整幅重绘。
4. **音符重建限流到 ~14Hz**，松手立刻补一次。听觉上完全无感。
5. **32 位整数掩码**替代 `BigInt`（快 4.6 倍），所有缓冲区预分配复用，零 GC 压力。
6. **命令式撤销**：画一笔只记「加了一条」，不再深拷贝 4 万个点。
7. **音频线程**预分配渲染缓冲，播放头回报限流到 30Hz。

实测（500 条笔迹 / 39700 个采样点）：

```
拖笔 400 次 pointerMove:
  平均 0.001 ms/次   最差 0.065 ms      ← 60fps 预算的 0.0%
  松手 pointerUp: 2.1 ms
buildNoteData:  3.1 ms（限流到 14Hz）
syncAll 整幅重建: 1.4 ms
画一整笔期间静态层从未重建 ✅
```

## 循环长度：已对齐原站

原站的时间轴是 **桌面画布装 16 拍**：

```js
const bpmToLoop = bpm => BARS * PULSES * 60 / bpm;   // 2 × 8 × 60/bpm = 960/bpm 秒
```

v1.2 之前我只给了 8 拍，所以**同样 BPM 下走完全程只要一半时间**，感觉上就是「速度太快」。

现在默认 16 拍，两边完全一致：

| BPM | 循环一圈 |
|---|---|
| 60 | 16.0 秒 |
| 80 | 12.0 秒 |
| 100 | 9.6 秒 |
| **120（默认）** | **8.0 秒** |
| 150 | 6.4 秒 |
| 200 | 4.8 秒 |

而且工具栏的「长度」下拉框旁边现在**直接显示秒数**（比如 `≈ 8.0 秒`），
拖速度滑块时会实时跟着变，不用再心算。

想更快/更慢就改 BPM；想让循环更长就改「长度」（4 / 8 / 16 / 32 / 64 拍）。
两个参数是独立的：BPM 管**拍子快慢**，长度管**画布装几拍**。

> 原站的 BPM 范围是 60–200，本程序给的是 40–220。

## v1.3 —— 播放相关的三个坑

### ① 第一次点播放：进度线狂转、没有声音

**根因**：音频节点是**第一次点播放时才创建**的，而 `pushNotes()` 在页面初始化时就跑了 ——
那时候还没有节点，`send()` 里的 `if (node)` 为假，**config 和 notes 全被丢掉**。

内核于是用构造函数的默认值 `stepN = 1000` 跑：

```
1000 采样/步 × 32 步 = 32000 采样 = 0.726 秒一圈
```

所以进度线以 0.7 秒一圈的速度疯转，而音符表是空的 → 没声音。

**修法**：`AudioEngine` 现在会**记住所有状态**（config / notes / 音量 / 鼓 / 节拍器），
节点建好后**整体重放一遍**。另外 `setPlaying(true)` 里加了兜底：
如果还没算过音符，立刻补算一次。

### ② 拖动速度滑块，声音会卡住

滑块 `oninput` 每移动一像素就触发一次，每次都重发 `config` + 重建音符表，
音频线程被反复打断。

**修法**：130ms 防抖，等手停下来才发。同时内核里改速度会**保持循环进度不跳**：

```js
// 播放中改速度：算出当前进度，换完速度再按进度重新锚定
const frac = ((this.t - this.anchor) % oldN) / oldN;
this.anchor = this.t - Math.round(frac * newStepN * d.steps);
```

实测位置偏移 **0.0000**（完全不跳）。

### ③ 再播放时有小卡顿

暂停时原来是**硬切**：直接把所有声部置零 → 波形从半空断掉，就是「咔」的一声。

**修法**：加了 25ms 的输出淡入淡出，淡干净之后才回收声部。
实测暂停瞬间的相邻采样跳变从"半空断掉"降到 **0.0132**（稳态波形本身就有 0.1234 的跳变，
也就是说淡出比正常波形还平滑）。

`node test-audio.js` 现在会检查这几点。

## 默认作品

页面打开时会展示 `DefaultDraw.txt` 里那幅画（**360 条笔迹**，戴蓝帽的动漫角色）。

这份数据是从 `DefaultDraw.txt` **编译**成 `default-piece.js` 的：

```bash
node build-default.js
```

**为什么不用 `fetch('DefaultDraw.txt')`？**
因为直接双击 `index.html` 时页面是 `file://` 协议，`fetch` 会被 CORS 拦掉。
包成 `.js` 用 `<script src>` 加载，`file://` 和 `http(s)://` 都能用。

所以：**改了 `DefaultDraw.txt` 之后要跑一次 `node build-default.js`**，否则页面还是旧的。

画布比例设成了 `ar = 0.62`。原数据里的 `a = 117` 是错的 —— 那是保存时浏览器窗口的比例
（当时开着 DevTools，窗口被压窄了）。0.62 是我拿牌子上"RHODES"几个字母的**字形纵横比**
当尺子逐个比例渲染对比出来的。

> 想换成你自己的画：点「⬇ 导入」贴数据 → 挑好比例 → 导入。
> 想换掉默认作品：把新的数据串存成 `DefaultDraw.txt`（整行一个串），再跑 `node build-default.js`。

## 手机

已经专门适配过：

- **设置收进抽屉** —— 顶栏只留播放/撤销/橡皮/清空，点 **⚙** 展开速度、音阶、画布比例等
- **触屏绘制** —— Pointer Events + `touch-action:none`，画的时候不会触发页面滚动/缩放
- **高 DPI** —— `devicePixelRatio` 最高按 2 倍渲染，手机上线条不糊
- **转屏自适应** —— `orientationchange` 后重排（延时 120ms / 400ms 两次，躲开浏览器动画期）
- **刘海屏安全区** —— `env(safe-area-inset-*)`
- **iOS 音频解锁** —— iOS 会把 Web Audio 走「铃声」通道，侧边静音开关一拨就彻底没声。
  程序会在第一次触摸时播一条**循环的静音音轨**，把页面切到「媒体播放」通道
- **横屏提示** —— 竖屏打开横向的画作时会提示「把手机横过来能画得更大」

> 提示：横向的画作在竖屏手机上只能占满宽度（390 屏 ≈ 366×226）。
> 转成横屏能拿到大约 2 倍多的绘制面积。

## 部署到 GitHub Pages

### 1. 在 GitHub 上新建一个空仓库

不要勾 "Add a README" / ".gitignore" / "license"，保持全空。

### 2. 推上去

```bash
cd /d D:\DrawMusic
git remote add origin https://github.com/你的用户名/你的仓库名.git
git push -u origin main
```

> 首次推送会要账号密码。**GitHub 从 2021 年起不再接受账户密码**，
> 需要去 `Settings → Developer settings → Personal access tokens` 建一个 token，
> 勾上 `repo` 权限，把 token 当密码填。

### 3. 开启 Pages

仓库页面 → **Settings** → 左侧 **Pages**：

- **Source**：`Deploy from a branch`
- **Branch**：`main` ＋ `/ (root)`
- 点 **Save**

等 1 分钟左右，访问：

```
https://你的用户名.github.io/你的仓库名/
```

### 4. 之后每次更新

```bash
git add -A
git commit -m "改了什么"
git push
```

Pages 会自动重新构建，一般 30 秒 ~ 1 分钟生效。

### 几个已经处理好的细节

- **全是相对路径** —— 站点会跑在 `用户名.github.io/仓库名/` 这个子路径下，
  所有 `<script src>` / `<link href>` 都是相对的，不会 404
- **`.nojekyll`** —— 跳过 GitHub 的 Jekyll 处理，避免文件名被误伤
- **`.gitattributes`** —— 网页文件统一 LF；`启动.bat` 保持 CRLF（否则 cmd 会出错）
- **没有构建步骤** —— 推上去的就是能跑的，不需要 Actions
